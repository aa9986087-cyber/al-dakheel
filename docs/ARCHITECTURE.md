# معمارية اللعب الجماعي — الدخيل

## الخلاصة

| القرار | الاختيار | السبب |
|---|---|---|
| مصدر الحقيقة | **خادم موثوق** (Authoritative server) | الأدوار سرّية: لو اعتمدنا على البث بين اللاعبين لكل جوال نسخة من أدوار الجميع |
| النقل | **WebSocket** ثنائي الاتجاه | الحركة تحتاج ١٥ تحديثًا في الثانية؛ الاستطلاع كل ثانية (مثل التكاتف) بطيء جدًا هنا |
| الاستضافة | **Cloudflare Worker + Durable Object لكل غرفة** | مجانية، بلا خادم تديره، والغرفة كائن واحد في الذاكرة يملك كل اتصالاتها |
| التطوير المحلي | **خادم Node** بنفس منطق الغرفة | تجربة فورية بـ`npm run dev`، ويصلح للنشر على أي VPS |
| الواجهة | JavaScript عادي + Canvas 2D، بلا bundler | نفس أسلوب مشاريعك السابقة: خفيف وسريع على الجوال |

```
 جوال/متصفح ──WebSocket──▶ Worker (/ws/CODE) ──▶ Durable Object «CODE»
     ▲                                              │  Room (server/room.js)
     └────────── حالة شخصية + مواقع ١٥/ث ◀──────────┘  tick كل 66ms
```

## ١. الغرف والانضمام

1. **إنشاء:** الصفحة تطلب `GET /api/new` فيرجع رمزًا من ٥ خانات (حروف وأرقام بلا المتشابهات مثل O/0 و I/1).
2. **الاتصال:** `wss://…/ws/CODE?create=1` للمنشئ، و`/ws/CODE` لمن ينضم. الـ Worker يوجّه الطلب إلى `ROOMS.idFromName(CODE)`؛ نفس الرمز يصل دائمًا لنفس الكائن في العالم.
3. **الرابط:** `https://…/?room=CODE` يفتح الصفحة والرمز مكتوب؛ يكتب اللاعب اسمه ويضغط انضمام. زر «مشاركة» يستخدم مشاركة الجوال (واتساب مباشرة).
4. **الرمز غير الموجود** يرجع `not_found` ولا يُنشئ غرفة فارغة بالخطأ.
5. **الهوية:** أول رسالة `hello` تحمل `token` محفوظًا في `localStorage` للغرفة. عند انقطاع الشبكة أو تحديث الصفحة يعود اللاعب لمقعده نفسه (حتى ٦٠ ثانية أثناء اللعب). لا حسابات ولا تسجيل دخول.
6. **المضيف:** أول من يدخل؛ وإذا خرج تنتقل الصلاحية تلقائيًا. المضيف وحده يغيّر الإعدادات ويبدأ ويعيد الجولة.
7. **الصالة:** اللاعبون يتجولون في الطائرة قبل البدء، يختارون لونًا غير مأخوذ، والمضيف يضبط الإعدادات (عدد الدخلاء، التهدئة، السرعة، الرؤية، المهام، أوقات النقاش والتصويت، الاجتماعات، كشف هوية المطرود).
8. **انتهاء الغرفة:** بعد ١٠ دقائق بلا أي متصل يُحذف الكائن من الذاكرة.

## ٢. المزامنة في الوقت الحقيقي

### الحركة (تنبؤ في الجهاز + تحقق في الخادم)

- الجوال يحرّك شخصيته **فورًا** بنفس كود التصادم المشترك (`public/shared/geom.js`) فلا يشعر اللاعب بأي تأخير.
- يرسل موقعه ١٥ مرة في الثانية `{t:"pos", x, y, tp}`.
- الخادم يتحقق: المسافة ضمن السرعة المسموحة، والنقطة قابلة للوقوف، والخط من الموقع السابق لا يخترق جدارًا أو بابًا مغلقًا.
- إذا رُفض الموقع، أو نقل الخادم اللاعب (إقصاء، فتحة، اجتماع)، يزيد العدّاد `tp` فيعرف الجوال أن عليه القفز للموقع الرسمي، ويتجاهل الخادم أي موقع قديم يحمل `tp` سابقًا.
- مواقع الآخرين تُرسل ١٥ مرة في الثانية وتُنعَّم في الجوال بالاستيفاء.

### ما يصل لكل لاعب (أسرار مفلترة من الخادم)

| البيانات | من يراها |
|---|---|
| دورك | أنت فقط |
| هوية الدخلاء | الدخلاء يرون بعضهم |
| موقع الأرواح | الأرواح فقط |
| دخيل داخل فتحة سرية | لا يُرسل موقعه للطاقم إطلاقًا |
| وفاة لاعب | تظهر للأحياء فقط بعد البلاغ أو الاجتماع |
| الأصوات | «صوّت/لم يصوّت» أثناء التصويت، والتفاصيل بعد النتيجة |
| شات الأرواح | الأرواح فقط |

### الأحداث (رسائل من الجوال، والخادم يقرر)

`kill` ، `report` ، `emergency` ، `task` ، `vote` ، `chat` ، `sabotage` ، `fix` ، `hold` ، `vent`.
كل رسالة يتحقق منها الخادم: المرحلة، الدور، الحياة، المسافة، التهدئة. لا شيء يُصدَّق لمجرد أن الجوال قاله.

### الحالة الشخصية

عند أي تغيير يرسل الخادم لكل لاعب `{t:"state"}` مفلترة له، تضم المرحلة واللاعبين والمهام والجثث والتخريب والاجتماع والنتيجة. الأوقات مطلقة بساعة الخادم، والجوال يصحّح فرق الساعة بأسرع `ping` (نفس فكرة `syncClock` في التكاتف) فتتطابق العدادات عند الجميع.

## ٣. مراحل الجولة

```
lobby ──start──▶ play ──report/emergency──▶ meeting ──▶ eject ──▶ play …
                   │                                        │
                   └──── الفوز ────▶ end ◀──── الفوز ───────┘ ──host──▶ lobby
```

- **play:** أول ٤ ثوانٍ شاشة الدور. الجرس والتخريب متاحان بعد ١٠ ثوانٍ.
- **meeting:** الجميع يُنقلون للمجلس، يُلغى التخريب، وقت نقاش ثم تصويت؛ ينتهي مبكرًا إذا صوّت كل الأحياء.
- **eject:** ٧ ثوانٍ: من طُرد وهل كان دخيلًا (حسب الإعداد) وكم بقي.
- **الفوز:** الطاقم بإنجاز كل المهام أو طرد/إقصاء كل الدخلاء؛ الدخلاء إذا تساوى عددهم مع الطاقم أو انتهى عدّاد تسرّب الوقود.

## ٤. لماذا Durable Objects وليس غيرها؟

| البديل | الحكم |
|---|---|
| D1 + استطلاع (مثل التكاتف) | ممتاز للأسئلة، لكن ١٥ تحديثًا/ث لكل لاعب يتجاوز حدود الكتابة ويضيف تأخيرًا |
| Supabase Realtime (مثل مبارزة Ashen Arena) | سريع، لكنه بث بين الأجهزة بلا خادم موثوق: الأدوار ستُكشف لمن يفتح أدوات المطور |
| WebRTC بين الأجهزة | معقّد ويحتاج خادم إشارة ومضيفًا موثوقًا |
| خادم Node دائم (Render/Fly/VPS) | يعمل مباشرة بـ`npm start`، لكنه يحتاج تشغيلًا دائمًا وقد ينام في الخطط المجانية |
| **Durable Object لكل غرفة** | خادم موثوق صغير لكل غرفة، WebSocket أصلي، مجاني لعشرات الجولات العائلية يوميًا |

الكائن يعمل بمؤقت ثابت ما دام فيه لاعبون؛ هذا مقصود لأن اللعبة حية. استهلاك جولة عائلية (١٠ لاعبين × ١٠ دقائق) صغير جدًا مقارنة بحدود الخطة المجانية.

## ٥. الأمان والعدل

- الخادم وحده يوزع الأدوار ويحفظها؛ الجوال لا يستلم دور غيره.
- تحقق المسافات للإقصاء والبلاغ والمهام والفتحات والجرس.
- تحقق الحركة يمنع اختراق الجدران والسرعة الزائدة.
- أسماء ونصوص الشات تُنظَّف وتُقصّ، وحجم الرسالة محدود (4KB).
- اللعبة للعائلة: «الإقصاء» إغماءة بنجوم تدور، بلا دم.
